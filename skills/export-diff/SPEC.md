# export-diff SPEC

The contract for this skill's pipeline. `scripts/render_diff.py` (diff parsing, page assembly, overlay), `scripts/engine.py` (matching and cell rendering), and `scripts/lint_diff.py` (I17 enforcement) implement it; any divergence between this file and observed behavior is a defect — determine which is wrong and fix both together.

## Pipeline (ordered)

1. **Acquire.** `--old/--new` → `diff -ruN` (exit > 1 aborts); or `--diff` reads an existing unified diff. An empty diff aborts.
2. **Group.** Split per-file chunks on `^diff `; take each chunk's old-side path from its `--- ` header; group key = first path component after stripping the diff root (`a`, the old directory name). Rootless files group as `(root)`.
3. **Split decision.** `always` | `never` | `auto` (auto splits when >1 group and the diff exceeds 150 KB).
4. **Parse & align.** The diff is parsed directly — no third-party layout. Per file, hunks; context lines become shared rows — the reliable anchors both sides align to. Raw hunk headers never reach the page: the skipped span between hunks renders as a separator labeled per side with that side's line range ("54-57 unchanged" / "49-52 unchanged"). Within each change block, del/ins lines pair by similarity (the best word-set Jaccard pair ≥ 0.4 anchors a recursive monotonic split; positional fallback), but that pairing is carried as a *semantic* row axis (per-side sem ids, equal iff counterparts) — the axis stationary demotion and run classification use. The *visual* table packs each side of a change block compactly (positional zip): no alignment-padding blanks are interjected between lines; a change row still holds its deletion and insertion cells in the same table row, so wrapped prose never drifts. When the new-side source file named by the diff is readable *and* every new-side line the diff carries matches it at its claimed number (validation gate — a drifted tree must never present wrong "unchanged" content), those separators become expanders — hidden rows behind each, plus a page-level Show/Hide-unchanged toggle — so the full file is readable in place; expansion redraws the overlay. Unverifiable sources leave the labeled separators unexpandable. Stages 5–10 then run per file.
5. **Collect & tokenize.** Only the changed sides of change rows are tokenized. Tokens: word runs and single punctuation characters; whitespace attaches to the preceding token (or the line's lead). Every equality test uses the token's case-folded key; original casing is kept for rendering. Lines partition into *segments*: consecutive file line numbers extend a segment; any jump (blank line, unchanged stretch, hunk boundary) starts a new one. All deleted tokens form stream D, inserted stream I.
6. **Tile** (greedy string tiling, RKR-GST family). Repeat: index every unconsumed 4-gram of I; for each unconsumed 4-gram of D, maximally extend every index hit, then trim punctuation-only boundary-line spillover (invariant I6) *before* ranking; discard candidates under 4 tokens / 12 word-chars; take the longest surviving tile, ties broken toward the smallest row distance; link its pairs mutually. Stop when no candidate survives.
7. **Refine.** Each unmatched token run bracketed by anchors is diffed (token-level, no minimum) against the counterpart's unmatched tokens between the bracketing anchors' destinations; `equal` tokens link.
8. **Runs.** Walk D's matched tokens in order; a run extends while destinations advance strictly monotonically in I, gaps stay ≤ 24 tokens per side and contain no foreign matches, and both sides stay within one segment. A run with ≥ 1 cross-row pair gets an id spanning both sides' full ranges, edits included. Two demotions then dissolve noise runs back into the edit stream: a run whose del-side and ins-side row ranges intersect (it never went anywhere — a real move lands on different rows), and a run under 30 word-characters (stock-phrase scale, cleared on both streams) — where substance is judged per *movement*, not per shard: runs connecting the same source segment to the same destination segment weigh together, so a short bullet head moves with the bullet body it belongs to. A stationary fold keeps its token matches — local in-place evidence. A demoted true move severs its matches and renders as plain deletion + addition ink, so no box ever holds un-inked text claiming a suppressed counterpart; when it still has tile-scale substance (≥ 12 word-chars) its two sides keep one shared box id, so the related fragments stay connected across the gutter.
9. **Rewrite flag.** Lines still under 50% token coverage pair by bag-of-words Jaccard (lowercased alphanumeric tokens ≥ 3 chars, threshold 0.4), greedily by score. A pair claims both lines wholesale: match links crossing the pair's boundary are severed, and marks re-derive from one canonical pairwise token diff (del side always first — the aligner is order-sensitive, and both sides must render the same alignment) whose equal spans still require exact-case equality (I10).
10. **Box assignment & render.** Every changed line rebuilds as plain text plus `<del>`/`<ins>` word ink — every unmatched token is inked (a wholly removed/added block is fully inked), and a matched pair differing only in casing inks as an ordinary mark. Every token carries a box id, emitted on its rendered element as `data-run`: moved-run tokens keep their run id; rewrite pairs share a line-level id; all remaining residue — changed tokens not claimed by a surviving run — groups into blobs — maximal residue stretches in a side's token stream, broken by an intervening run, a severed-pair box, or a segment boundary; a blob joins or crosses a line boundary only via a *substantive* span (word content, or a wholly word-free changed line, which still needs a box) — a punctuation-only span on a wordful line stays unassigned and attaches to a neighboring group at render — and blobs merge into one box only on evidence: a surviving token match between them (every surviving residue match is local by construction — same-row edits, or stationary folds). A merged two-sided box gets a connector; an unlinked blob (pure removal or addition, or a leftover fragment between moves) stands alone — residue separated by moved content is separate boxes, never one scattered multi-fragment box. Mark tokens and word-free fragments attach to the following group on their line (trailing to the preceding), so edge deletions sit inside the box of the content they flank. Adjacent boxes on one line reserve shared-border room as a trailing 4px margin on the outgoing element (`ne`) — trailing, so at a soft-wrap boundary the room dies at the line end instead of indenting the wrapped row.
11. **Overlay.** The page is our own DOM: one table per file, a 48px gutter column, `del`/`ins` as plain inline text, line-height owned by the page CSS. Nothing in the table may paint over the gutter — connectors travel it; unchanged-span separators tint both text columns light gray but keep their gutter cell transparent. An in-page script measures the rendered text per file and draws, beneath the text layer, in three paint layers — box fills, then word ink, then outlines and connectors, so ink can never cover an outline. Row bands normalize to exactly one line-box height around each measured row's center while retaining the measured glyph extent for the ink. Every vertical box edge — outer or interior — lies on a line-box boundary: the leading between lines is the reserved border lane, so every edge has the identical half-leading clearance from the glyphs, adjacent lines' bands tile exactly (shared single lines), and a blank line — a full empty line box — keeps stacked boxes naturally separate. The page's vertical rhythm is an integer grid (line-height 24px, integer chrome metrics), so those boundaries land on whole pixels, and all rectilinear geometry (boxes, fills, ink) renders with `crispEdges` — no fractional-position antialiasing; connectors keep smooth curves. One box per (id, side): gray outline, red fill left / green fill right, horizontal edges at exactly content ± 2px (spaces included), near-adjacent vertical edges midpoint-snapped so shared borders are the identical single line — plus a gutter connector for every id present on both sides. Word ink (`del`/`ins`) is painted per element per band at the exact text extents, horizontal and vertical (the glyph rect), keeping it at least 2px clear of every outline. Hovering anywhere inside a box (geometric hit-test, steady across rows) highlights both boxes and the connector — darker gray plus an interior-clipped inner glow, width unchanged — and pulls them to front; clicking pins exactly one id (darkest gray, same glow; click again to unpin; pinned reclaims front when hover ends). Right-clicking a box copies a block reference to the clipboard — per present side, an ALL-CAPS marker line (`OLD: path:lines` / `NEW: path:lines`) followed by that side's verbatim contents on their own lines — a composite handle: paths and line ranges from the diff for precision, the quotes as grep-anchors that survive line drift; no change-kind label (kinds blur — a box is often move and change at once, and movedness is relative to the row pairing); a toast confirms the copy.
12. **Assemble & lint.** Split mode: one page per group plus an `index.html` viewer (dropdown, totals, legend, hash routing, iframe). Single mode: one `index.html`. Every rendered page is linted against I17 (`scripts/lint_diff.py`, also runnable standalone); violations print as `LINT` lines and a count in the stats. Per-page/section stats print to stdout (moved runs, change blocks, rewrite pairs).

## Invariants

Everything that must hold on every output, ordered by the stage that owns it.

- **I1 — Text fidelity** (stage 5/10). Tokenization is a lossless partition: a rebuilt line reproduces its text character-for-character; markup wraps, never edits.
- **I2 — Context immunity** (stage 5). Unchanged (context) lines are never tokenized, matched, or rewritten.
- **I3 — Document-order authority** (stages 6/8). Matching may treat as contiguous only what the file makes contiguous: no tile or run spans a segment seam on either side. Unchanged regions thus act as hard separators even though they contribute no tokens — their protection is positional, not just textual.
- **I4 — Mutual 1:1 matching** (stages 6/7). Every matched token's counterpart points back to it; no token matches twice.
- **I5 — Anchor exactness** (stage 6). Tiles link only exactly-equal (case-folded) token runs meeting the minimums (4 tokens / 12 word-chars).
- **I6 — Edge substance** (stage 6). A tile crosses a line boundary only if its portion on the boundary line contains an alphanumeric token; punctuation-only spillover is trimmed, whichever side it occurs on.
- **I7 — Refinement confinement** (stage 7). Refinement links only tokens lying between its bracketing anchors' destinations; it never crosses an anchor.
- **I8 — Run contiguity** (stage 8). Within a run: destinations strictly monotonic, gaps ≤ 24 tokens/side, no foreign matches inside, one segment per side. Tokens before a run's first anchor or after its last belong to no run.
- **I9 — Total boxing** (stage 10). Every changed token belongs to exactly one box; run ids exist only for cross-row (moved) runs that survive demotion; residue blobs share an id only through surviving token matches, which are local by construction; an id present on both sides gets exactly one connector, an id on one side gets none.
- **I10 — Mark completeness** (stage 10). Every unmatched token is inked — a wholly removed or added block is fully inked; case-only differences ink as ordinary marks, never hidden and never given a distinct style.
- **I11 — Box geometry** (stage 11). Horizontal box edges sit at exactly content ± 2px with spaces treated as ordinary characters; vertical edges lie on line-box boundaries — the reserved border lane in the leading — giving every edge the identical half-leading clearance and every box on a row the identical height; borders shared between boxes are the identical coordinate rendering as one line; adjacent boxes on a line have reserved room; rectilinear geometry renders on the pixel grid (`crispEdges`), never with fractional-position antialiasing; word ink spans exactly the glyph rect and is painted beneath outlines.
- **I12 — Self-containment** (stage 12). Pages reference no external resources — CSS/JS inline; section pages and `index.html` are colocated siblings.
- **I13 — Single pass** (stage 4→10). The engine consumes the parsed diff only; rendered pages are terminal artifacts — to change anything, regenerate from the diff.
- **I14 — Progress** (stage 6). Every tiling round consumes a qualifying tile or terminates the loop; no code path may leave a round's state unchanged. (Candidates are trimmed before ranking precisely so a selected best is always consumable.)
- **I15 — Explicit color** (stage 11). Every rendered color is an explicit value from the red / green / neutral ramps; no opacity is used anywhere, so overlapping strokes cannot compound and rendering is independent of what sits beneath. Sole sanctioned soft-alpha effect: the emphasis glow (I16).
- **I16 — Pin singularity** (stage 11, interaction). At most one box pair is pinned; a pinned pair stays highlighted through hover-out and reclaims the front when a hover ends; clicking the pinned pair unpins it; pinning another replaces the pin. Emphasis darkens the stroke along the neutral ramp (pin darker than hover) and adds an *inner* glow — a wide blurred stroke clipped to the box's own interior — so emphasis marks what belongs to the box without lighting sibling boxes' content; stroke width and fills never change, so crisp lines stay crisp and the emphasized path's whole perimeter reads uniformly. Connectors, having no interior, glow with a small drop-shadow instead.
- **I17 — Honest pairing** (stages 8–10; enforced by `scripts/lint_diff.py` on every render). A box id present on only one side is completely inked — it claims no counterpart. For a two-sided box, the un-inked text is identical on both sides as a word multiset (whitespace and matched punctuation attach to neighboring boxes; a stationary fold may reorder within its box, so sequence equality is not guaranteed). In a changed cell, every non-whitespace character sits inside a boxed element.

## Thresholds

| Constant | Value | Meaning |
|---|---|---|
| `MIN_TILE_TOKENS` | 4 | minimum anchor length in tokens |
| `MIN_TILE_CHARS` | 12 | minimum anchor word-chars; also the severed-pair substance floor |
| `RUN_GAP_CAP` | 24 | max unmatched tokens bridged inside a run, per side |
| `JACCARD` | 0.4 | word-set floor: rewrite pairing and change-block row alignment |
| `RUN_MIN_CHARS` | 30 | word-chars below which a run demotes into the residue |
| `AUTO_SPLIT_BYTES` | 150 000 | auto split-mode diff size floor |

Smaller anchors catch more but risk matching stock phrases across unrelated lines.

## Color chart

Explicit ramps only (see I15). Light / dark:

| Element | Light | Dark |
|---|---|---|
| box fill (removed / added) | #ffe6e8 / #def1e3 | #301b1e / #142a20 |
| word ink (removed / added) | #ffc5c9 / #b4e0be | #6b2b2b / #21542e |
| outline & connector (rest → hover → pin) | #8b949e → #57606a → #24292f | #6e7681 → #adbac7 → #cdd9e5 |

Stroke width: 1px always. Emphasis: inner glow reaching 1px inside the edge (2px stroke, 1px blur, clipped to the box interior) in the stroke's own color for both hover and pin; pin differs by the darker stroke. Connectors: 1.5px drop-shadow.

## Known limits

- Marks are token-level, not character-level.
- Changed lines lose syntax-highlight coloring (rebuilt as plain text plus marks).
- Row pairing within a change block is similarity-anchored with positional fallback; content that moves against it shows as moved runs or severed pairs (by design) — rows are never re-aligned to chase moves.
- A move rewritten below the Jaccard floor renders as a rewrite pair (crossing connector) or plain removal + addition.
- Box geometry is measured in-browser; it redraws on resize and fold toggles only.
