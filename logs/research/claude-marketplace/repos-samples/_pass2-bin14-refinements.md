## Proposed description sharpenings

> Format: `<role> > <existing-path>` — what the existing description misses; supporting samples; sharpening suggestion

- `Tag and release lifecycle > Single lifetime tag with drift` — `hwuiwon--autotune.md` — the autotune case has `plugin.json` at `0.3.0` while only `0.1.0` is tagged; subsequent bump commits exist on `main` without tags. Sharpening: clarify that "drift" specifically means the tag is older than the manifest version, with intermediate untagged version-bump commits. Existing description should make explicit that the manifest is ahead of the tagged release.
- `Version coordination > Multi-artifact lockstep across N>2 manifests` — `hwuiwon--autotune.md` — three locations (marketplace.json, plugin.json, package.json) all carry `"version": "0.3.0"` independently with no sync gate. Sharpening: clarify whether "lockstep" implies enforcement (e.g., a CI gate or pre-commit hook) or just current alignment. autotune is current-aligned but unenforced; iVintik/codeharness has the same shape (package.json + plugin.json) WITH a CI gate. Same path covers both, but enforcement varies.
- `Marketplace manifest layout > No marketplace manifest (plugin source repo only)` — `iVintik--codeharness.md` — codeharness ships no marketplace.json but has a separate `iVintik/private-claude-marketplace` aggregator that receives `repository_dispatch` events from `release.yml`. The "plugin source repo only" framing misses that the repo is paired with an external aggregator via cross-repo dispatch. Sharpening: differentiate (a) "no marketplace anywhere, install via direct git" from (b) "no marketplace IN THIS repo, separate aggregator repo holds the marketplace entry".
- `SessionStart matcher scope > Empty matcher (all sub-events)` — `iVintik--codeharness.md` uses explicit `matcher: "*"` (rather than omitted matcher). Sharpening: note that `matcher: "*"` and omitted matcher are equivalent semantically; surface both forms. The cost analysis (expensive version check + potential `npm install` on every clear/compact, not just startup) applies to both.
- `Per-plugin discoverability metadata > Bare-minimum (name, version, description only)` — `iVintik--codeharness.md` ships a 236-byte `plugin.json` with only `name`, `version`, `description` — no `category`, `tags`, `keywords`, `author`, or `homepage`. Sharpening: add the byte size and the relationship with optional external aggregator metadata (where the aggregator may supply discoverability fields the plugin manifest omits).
- `User configuration and authentication > Native userConfig with ${user_config.KEY} substitution` — `includeHasan--prospect-studio.md` — `${user_config.<key>}` flows into both `.mcp.json` env vars AND outbound HTTP `Authorization` headers for remote MCPs, with `sensitive: true` keeping secrets in OS keychain. Sharpening: note that substitution destinations include remote-MCP auth headers (not just env vars), and that combining with `sensitive: true` provides keychain-backed bearer-token injection.
- `Dependency installation > SessionStart hook → npm install local to plugin` — `includeHasan--prospect-studio.md` — install location is specifically `${CLAUDE_PLUGIN_ROOT}/mcp-server/node_modules` (NOT `${CLAUDE_PLUGIN_DATA}`) because ESM `import` walks the filesystem from the importer; `NODE_PATH` is CJS-only and silently ignored by ESM. Sharpening: ESM-vs-CJS rationale belongs in this path's description. Cross-references: Arcanon-hub/arcanon takes the same stance with different change-detection (diff-q vs sha256).
- `Hook failure posture > Silent fail-open (exit 0 always, retry every hook)` — `includeHasan--prospect-studio.md` — three layers of fail-open (the `bash -c … || exit 0` trampoline, the Python script's try/except → sys.exit(0), and the explicit "exit 0 unconditionally" in install-deps.sh). Sharpening: characterize as "stacked fail-open" — multiple independent layers each defaulting to exit 0 — distinct from a single layer using exit 0.

- **AGENTS.md naming collision**: iVintik/codeharness has both an `AGENTS.md` file at root (OpenAI-style cross-runtime instruction) AND an `agents/` directory with `.md` files (Claude Code agent definitions).
