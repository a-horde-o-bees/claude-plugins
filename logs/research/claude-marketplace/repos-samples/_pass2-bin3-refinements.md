## Proposed description sharpenings

> Format: `<role> > <existing-path>` — what the existing description misses; supporting samples; sharpening suggestion

- `Source layout > Dual tree with sync gate` — `ChanMeng666--claude-code-audio-hooks.md` — Existing description covers the mechanism (`cp + cmp -s`, `--check` mode, CI gate). Could sharpen by noting the rationale recurs as "plugin caching copies `plugins/<name>/` as a unit" plus the regression mode: an out-of-sync packaged copy makes the tagged release ship pre-fix code even after the canonical copy has been fixed. v5.1.0 in the audio-hooks sample is a documented case of this exact failure (CHANGELOG calls it out as the reason CI was added).

- `Version coordination > Triple-file version (build manifest joins)` — `Chachamaru127--claude-code-harness.md` — Existing description mentions the third file as a "build manifest." Could add: when the third file is upstream of the manifest (codegen direction), drift detection runs in two directions — pre-commit hook syncs VERSION → plugin.json, and `check-consistency.sh` verifies committed manifests match what `harness sync` would produce.
