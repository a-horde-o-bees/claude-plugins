# Design — settings-file host registry

Borrow the harness's own configuration convention rather than inventing one: `settings.<skill-name>.json` sits beside `settings.json` at each scope, is owned by the user (never superseded by plugin updates, unlike anything inside a skills folder), and is discoverable from any invocation — home for the user scope, cwd walk-up (CLAUDE_PROJECT_DIR shortcut when exported) for the project scope, the same discovery the harness uses. Hosts bind against the running tool's sibling suite (`Path(__file__)` derivation), so plugin supersession regenerates hosts against the new versions automatically. Auto-inclusion is scoped to own-suite invocations so gates get hosts for free while fixture and single-file runs stay exact. A malformed settings file is a loud error, not a skipped read.
